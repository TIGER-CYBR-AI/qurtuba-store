# مشروع تطبيق قرطبة — Android / Flutter

هذا مشروع أولي متكامل البنية لتطبيق متجر قرطبة، مع واجهة زبائن ولوحة إدارة داخل تطبيق Android واحد، وملف GitHub Actions لبناء APK تلقائياً.

## مهم قبل الاستخدام
- المشروع يحتاج إعداد Supabase مرة واحدة حتى تعمل قاعدة البيانات وتسجيل الدخول وتخزين الصور عبر الإنترنت.
- لا يوجد سيرفر خاص مطلوب منك أو من صاحب المحل؛ Supabase خدمة سحابية مُدارة. خطتها المجانية وحدودها وشروط توفرها قد تتغير.
- بدون إعداد `SUPABASE_URL` و`SUPABASE_ANON_KEY` سيعمل التطبيق بواجهة توضيحية، لكن البيانات والحجوزات لن تتزامن عبر الإنترنت.
- لا تضع `service_role` key داخل التطبيق. استخدم فقط مفتاح `anon/publishable` مع سياسات RLS.
- هذا المشروع لم يُختبر على جهاز Android فعلي في بيئة إنشاء الملف الحالية. GitHub Actions سيجري البناء، وإذا فشل ستظهر سجلات الخطأ في Actions.

## البناء التلقائي
1. أنشئ مستودع GitHub جديداً وارفع جميع محتويات هذا المجلد إلى جذر المستودع.
2. افتح تبويب **Actions** وفعّل GitHub Actions إن طلب منك ذلك.
3. شغّل workflow باسم **Build Qurtuba Android APK** من تبويب Actions، أو ادفع commit جديداً إلى الفرع الرئيسي.
4. بعد نجاح البناء، افتح تشغيل الـ workflow ثم قسم **Artifacts** ونزّل `qurtuba-android-apk`.

## إعداد Supabase
1. أنشئ مشروعاً جديداً في Supabase.
2. من SQL Editor نفّذ محتوى `supabase/schema.sql`.
3. أنشئ bucket باسم `product-images` واجعله Public لعرض صور المنتجات.
4. من Project Settings / API انسخ Project URL وPublishable/anon key.
5. في GitHub افتح Settings → Secrets and variables → Actions وأضف:
   - `SUPABASE_URL`
   - `SUPABASE_ANON_KEY`
6. شغّل البناء مجدداً. تُمرر القيم وقت البناء ولا تحتاج تعديل ملفات الكود.
7. أنشئ مستخدم صاحب المحل من Supabase Authentication → Users، ثم أضف UUID الخاص به في جدول `admins` حسب تعليمات SQL.

## محتوى النسخة الحالية
- واجهة عربية RTL باسم قرطبة.
- عرض الأقسام والمنتجات والبحث.
- تسجيل دخول للإدارة.
- إضافة/تعديل/حذف الأقسام والمنتجات.
- رفع صور المنتجات إلى Supabase Storage.
- استقبال الحجوزات برقم مرجعي وتحديث حالتها من لوحة الإدارة.
- سياسات RLS أساسية في SQL لتقييد إدارة البيانات على المستخدمين المسجلين ضمن جدول admins.

## ملاحظات الأمان والإطلاق
- راجع سياسات SQL قبل نشر التطبيق على نطاق واسع، وجرّب مستخدم زبون ومستخدم إدارة منفصلين.
- لا تستخدم بيانات حقيقية حساسة أثناء الاختبار.
- الحجز العام يسمح للزائر بإرسال اسمه ورقم هاتفه؛ احمِ هذه البيانات وعرّف الزبائن بسياسة الخصوصية قبل النشر.
- لا يوجد دفع إلكتروني.
